# 部署向导设计

## 概述

一键部署 DST 服务器：选择服务器 → 选择模板 → 实时进度 → 完成。

区别于当前的一次性 HTTP 调用（阻塞 10 分钟无反馈），新部署向导使用任务追踪系统，实时展示每个步骤的进度。

## 流程

```
步骤1: 选择服务器
  └─ 已纳管的在线服务器列表
  └─ 或 [纳管新服务器]（跳转到添加服务器流程）

步骤2: 选择模板
  └─ 服务器模板列表（已整合模板系统）
  └─ 预览模板详情（绑定预设、模组列表）

步骤3: 确认配置
  └─ 自动生成的配置摘要
  └─ 集群名称、端口、密码

步骤4: 部署执行（实时进度）
  └─ 进度条 + 步骤说明 + 日志流
```

## 技术实现

- 平台后端创建 `deploy_task` 记录
- Node 通过 `event.task.progress` 推送进度（进度百分比 + 日志行）
- 前端通过 STOMP `/topic/tasks/{taskId}` 接收实时更新
- 取消操作：发送 `dst.stop` + 清理部分下载文件

## 错误处理

- 每步失败可重试（单独重试该步骤）
- 已成功的步骤跳过（幂等）
- 安装 SteamCMD 失败 → 检查网络/磁盘
- 安装 DST 失败 → 检查磁盘空间 + SteamCMD 状态
- 启动失败 → 查看日志诊断
